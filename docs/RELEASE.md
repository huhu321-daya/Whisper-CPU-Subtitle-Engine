# 安装与发布说明

本文件面向**普通用户**，说明如何获取与部署成品引擎。
开发者编译源码请看 [BUILD.md](BUILD.md)，仓库结构见 [README.md](../README.md)。

---

## 一、获取成品

本仓库不包含编译产物，成品 exe 发布于 **Releases** 页面。

只下载 **`main64.exe`** 一个文件即可，约 4.3 MB，静态链接，无需额外 DLL。

如果 Releases 页面没有对应版本，说明该版本仅提供源码，需自行编译。

> 担心下载不完整的用户，可在 Releases 页面点击附件旁的校验图标查看 SHA-256，与本地文件比对。普通用户无需理会。

---

## 二、安装步骤

### 1. 确认目标目录

宿主程序会从一个**固定的引擎目录**加载本引擎。该目录通常已存在一个同名的引擎文件。

> 不同宿主程序的目录位置不同，请以实际安装路径为准。本引擎**只替换 exe 文件本身**，不修改宿主程序的其他任何文件。

### 2. 备份原文件

替换前建议先备份原引擎，以便需要时还原：

```powershell
Copy-Item "<引擎目录>\main64.exe" "<引擎目录>\main64.exe.bak"
```

### 3. 放入新文件

将下载的 `main64.exe` 复制到该目录，**文件名必须保持 `main64.exe`**。
宿主程序的引擎加载器按固定名称查找，改名后不会出现在引擎选择列表中。

```powershell
Copy-Item .\main64.exe "<引擎目录>\main64.exe" -Force
```

该操作通常需要管理员权限。

### 4. 准备模型

引擎需要 ggml 格式的模型文件，放在宿主程序的模型目录下：

```
https://huggingface.co/ggerganov/whisper.cpp/tree/main
```

| 模型 | 体积 | 速度 | 准确率 |
|---|---|---|---|
| `ggml-tiny.bin` | 77 MB | 最快 | 一般 |
| `ggml-base.bin` | 148 MB | 中等 | 较好 |
| `ggml-small.bin` | 488 MB | 较慢 | 好 |

内存充足的机器建议 `ggml-base.bin`。`tiny` 适合低配机器，但中文识别错误率偏高。

### 5. 启用

启动播放，在音频设置中选择本引擎并开启字幕识别功能。

首次运行会加载模型，需要数秒。之后进入正常的实时识别流程。

---

## 三、验证是否工作

引擎会把运行日志写到系统临时目录：

```
%TEMP%\main64_engine.log
```

正常启动应包含类似内容：

```
Whisper CPU engine, tiny model is ready
```

若日志文件不存在或内容为空，说明引擎未能启动。

## 四、常见问题

### 引擎列表中看不到本引擎

- 文件名是否为 `main64.exe`
- 文件是否放入了正确的引擎目录
- 是否被安全软件拦截

### 提示缺少 DLL

本引擎为静态链接，理论上不依赖任何第三方 DLL。
若宿主程序在该目录下有自己的完整性检查，可能提示缺失。此时把一个同目录下已有的其他引擎文件作为占位符放入即可，本引擎**运行时不会加载它**。

### 模型加载失败

- 确认模型文件是 ggml 格式（文件名形如 `ggml-*.bin`）
- 确认模型放入了宿主程序的模型目录
- 检查磁盘空间是否充足

### 延迟偏高

- 换用 `ggml-tiny.bin`
- 关闭其他占用 CPU 的程序
- 本引擎默认 3 秒识别窗口，属于设计值，调小会影响断句完整性

### 识别准确率不足

- 换用 `ggml-base.bin` 或 `ggml-small.bin`
- 确认控制报文中的语言标识正确

## 五、卸载与还原

删除本引擎文件，将备份文件还原为原名即可：

```powershell
Remove-Item "<引擎目录>\main64.exe"
Rename-Item "<引擎目录>\main64.exe.bak" "main64.exe"
```

引擎不在系统任何位置留驻，不写注册表，不安装服务。除 exe 文件与日志外无其他痕迹。

## 六、发布者说明

### 打包清单

Releases 附件**只需一个文件**：

```
main64.exe
```

该文件放在仓库的 `dist/` 目录下。`dist/` 已被 `.gitignore` 排除，不会被提交进仓库，只用于上传到 Releases。

源码、头文件、构建脚本**不需要**放进附件，它们在仓库里。也不建议额外放校验文件——GitHub 会在附件旁自动显示 SHA-256。

### 发布前的自检项

| 检查 | 方法 |
|---|---|
| 体积约 4.3 MB | `Get-Item main64.exe` |
| 导入表仅 3 个 DLL | `objdump -p main64.exe \| findstr "DLL Name"` |
| 无 GPU 后端残留 | `strings main64.exe \| findstr /i "cuda vulkan opencl coreml"` |
| 关键符号存在 | `nm main64.exe \| findstr "ggml_backend_cpu_reg whisper_full_with_state"` |
| 可独立启动 | 双击运行，无参时等待 IPC 后主动退出（退出码 1） |

### 版本号约定

建议采用 `v<主版本>.<次版本>` 形式，并在 Release 说明中注明所对应的 whisper.cpp 版本，便于使用者对照编译。
